# FoodProof Fit — 120-second demonstration script

## Before recording

- Start the web application and confirm the **Analyze** and **Evals** views open.
- Keep the three Nature Valley photographs available for the live-photo proof point.
- Use the built-in demo scenarios for a repeatable recording. Clearly call them synthetic cases.
- Do not claim general image accuracy. Say that four real photographed products completed the full path, one weak set correctly triggered a retake, and broader vision validation is still required.

## 0–12 seconds — the problem

“A food package gives everyone the same dense label, even though people care about different allergens, portions and daily targets. FoodProof Fit turns that label into a personal Evidence Card without declaring a food healthy, diagnosing anyone, or guaranteeing allergy safety.”

Show the three required photographs and the optional personal profile.

## 12–42 seconds — the useful journey

1. Select **Demo 1 — Daily-goal contribution**.
2. Continue to the confirmation screen.
3. Say: “Vision is fallible, so the user must confirm or correct the extracted facts before any calculation.”
4. Change the portion if desired, confirm it, and show the calorie, nutrient and daily-target contribution cards.
5. Point to the FDA citation and say: “The wording is grounded in a curated regulatory source; the arithmetic is deterministic.”
## 42–60 seconds — live alternatives

Choose **Lower sodium** in **Find a better-aligned alternative** and run the live search.

“The shortlist is restricted to U.S.-listed products in the same category, normalized per 100 grams, and checked against the profile. It is not a universal healthier-product verdict. When added-sugar evidence is missing, the system refuses to substitute total sugar.”

## 60–78 seconds — personalization and safety

1. Select **Demo 2 — Personal allergen alert** and show the declared milk match.
2. Say: “This is a label-to-profile match, not allergy clearance.”
3. Select **Demo 3 — Safety-boundary refusal**.
4. Say: “Even with relevant label text, the system refuses to promise that a product is safe for a child with a severe allergy.”

## 78–105 seconds — quality evidence

Open **Evals** and show the eight separate release gates.

“FoodProof Fit passes 52 defined golden cases: unsafe refusal, safe-question usability, exact calculations, FDA retrieval, personalization, fair-comparison, barcode cross-check and alternative-finder rules. I keep vision readiness separate because four completed photographed products are still not enough for a general accuracy percentage.”

Open **Compare** and switch between labelled serving and per 100 g. Point out that the app compares each nutrient on a common basis and does not issue one universal “healthier” verdict. The interface explicitly labels the built-in example as synthetic.

Briefly show the architecture diagram at the bottom of Evals: AI reads, a person confirms, deterministic tools calculate and match, and LangGraph routes the bounded evidence workflow.

## 105–114 seconds — privacy and continuity

After a real-photo analysis, open **History** and say: “The confirmed structured result can be reopened during this browser session. Original photographs and personal profile inputs are not saved, and closing the tab clears the list.”

## 114–120 seconds — close

“FoodProof Fit demonstrates the production pattern I care about: AI for perception and explanation, deterministic tools for calculations, a human confirmation gate, cited evidence and explicit refusal boundaries.”

## Backup if the live API is unavailable

Use the three built-in scenarios. They exercise the same confirmation and result interfaces with clearly labelled synthetic values. If the live catalogue is unavailable, show the safe no-result message and explain that the confirmed FoodProof Fit analysis remains unchanged. Never present the fallback as live vision extraction.
